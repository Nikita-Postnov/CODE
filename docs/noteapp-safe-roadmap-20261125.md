# План безопасного развития NP Notes

Статус: проектирование оставшихся функций, **не означает, что они реализованы**. Рабочая ветка `main` и формат `Data` не меняются до ручной проверки.

## 1. Восстановление несохранённых правок

- Текущий путь: `noteapp/app/autosave.py`, `persistence.py`.
- Уже добавлено: повтор после ошибки записи с сохранением признака несохранённого текста; отказ от выхода при ошибке сохранения; атомарная резервная копия и запрет перезаписи при ошибке её создания.
- Реализован Windows-only зашифрованный DPAPI-черновик по UUID заметки, с атомарной записью и предложением принять/отклонить после загрузки; подтверждение обязательно, формат note.json не изменён. Путь Data/Recovery.\n- Дальше: TTL, предупреждение при многократном сбое DPAPI, ограничения для нескольких одновременно запущенных экземпляров и UI сравнения версий перед восстановлением.
- При запуске предлагается восстановление, если зашифрованный снимок отличается от сохранённой заметки; без явного согласия файл заметки не заменяется. Перед внедрением проверить сценарий, когда сохранённая заметка новее черновика.
- Тесты: реализованы DPAPI round-trip, блокировка незашифрованной записи на Linux, отмена и принятие восстановления, очистка после успешного сохранения, обработка устаревшего UUID. Дальше: внезапный kill, выключение питания между записью и rename, два запуска приложения, сравнение нового сохранённого текста.

## 2. Защита конфиденциальных данных

- Существующее поле `password_manager` может содержать текст; автоматическое шифрование текущих файлов **не включено**.
- Спроектировать versioned envelope с Windows DPAPI для секретных полей и явно обрабатывать ситуацию, когда другой ПК / профиль не может расшифровать данные.
- До миграции: выбор способа резервного копирования, явно согласованный экспорт, невозможность тихой потери данных.
- Тесты: чтение legacy, round-trip на Windows, перенос на другой профиль, отмена миграции, повреждённый зашифрованный payload, восстановление из backup.
- Не хранить DPAPI ключ, токен или пароль внутри репозитория.

## 3. Организация заметок

- Добавлено: виртуальное представление «Без тегов», не изменяющее формат note.json.
- Сначала проверить действующие теги, избранное, закрепление и сортировку.
- Предлагаемый новый UX: избранное / недавние / без тегов как виртуальные представления (без изменения схемы JSON); только после этого реальные папки, если они необходимы.
- Тесты: одинаковые заголовки, 10 000 заметок, удалённый тег, перенос между фильтрами без изменения UUID.

## 4. Редактор

- Уже имеются rich text, таблицы, checkbox, ссылки и заголовки; не дублировать.
- Уже добавлено: Ctrl+Shift+F (поиск), Ctrl+Shift+K (переключение чекбокса с Undo).
- Следующие задачи: доступная навигация, Undo/Redo для операций над таблицами, точечное выделение найденного.
- Тесты с Qt: сохранение/загрузка HTML, выделение, undo, вставка Unicode, изображения, авто-ссылки.

## 5. Виджет на рабочем столе

- Добавлено: копирование текста через контекстное меню без изменения хранилища, переключатель поверх окон, непрозрачность 60–100% с сохранением в QSettings.
- Дальше: проверка на нескольких мониторах и DPI, доступные размеры элементов и проверка контекстного меню Qt в Windows.
- Тесты: повторный запуск, смена DPI, недоступный экран, закрытие во время записи.

## 6. Производительность

- Добавлено: поиск «Везде» выполняет быструю проверку метаданных до преобразования HTML.
- Дальше: измерение времени старта, открытия заметки и поиска на 100 / 1 000 / 10 000 заметок, без содержимого пользовательских файлов в телеметрии.
- Оптимизировать только после исходных и итоговых измерений.

## Критерии объединения в main

1. Windows + Linux CI зелёный, включая тесты переносимости и сохранения.
2. Ручной Qt smoke test под Windows 11.
3. Пробный запуск на анонимизированной копии Data; сравнение файлов и обратная совместимость.
4. Отдельный backup Data до первого обновления; проверенный rollback Choice.
5. До успешной проверки PR остаётся черновиком и не сливается автоматически.


## Первый запуск в пустой тестовой папке

При запуске изолированной тестовой копии пользовательские заметки **не копируются** в `Data`. Пустой список слева — ожидаемый результат. Вместо пустого редактора должен отображаться стартовый экран «Пока нет заметок», кнопка «Создать заметку» и окно нормального размера. После создания тестовой заметки появляются редактор и инструменты. Этот сценарий проверяется автоматическими тестами, включая Qt offscreen.

## Изолированная проверка Windows перед слиянием

Предварительная подготовка (скачать файл `tools/preview_np_notes_pr83.ps1` именно из ветки PR):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\preview_np_notes_pr83.ps1 -LauncherRoot 'C:\WORK\NP\Launcher'
```

Скрипт **только подготавливает** тестовую копию. Он скачивает текущий HEAD ветки PR, создаёт новую папку в `%TEMP%\NP_Notes_PR83_<SHA>`, кладёт туда только программный пакет, пустой `Data` и маркер `Choice.pyw`. Рабочая папка `Launcher\Data` не копируется и не изменяется. Если нужно, в отдельной тестовой сессии можно добавить `-Launch`; предварительно убедиться, что установлен совместимый `Launcher\Runtime`.

Ручной smoke test (только на тестовых заметках):
1. Создать тестовую заметку; проверить текст, чекбоксы, Undo, поиск Ctrl+G, «Недавние», «Без тегов».
2. Проверить напоминания «Каждый час» и «По выходным», в том числе после перезапуска.
3. В виджете проверить копирование, прозрачность и «Поверх окон» после повторного открытия.
4. Для восстановления проверить сохранение зашифрованного черновика в тестовом `Data\Recovery`, аварийное завершение **только тестового процесса**, повторный запуск и выбор восстановления; сравнить состояние `note.json`.
5. Убедиться, что реальная `Launcher\Data` не затронута, и только затем готовить отдельную резервную копию для рабочего обновления.

Запрещено использовать рабочие заметки в этом сценарии до завершения проверки.
