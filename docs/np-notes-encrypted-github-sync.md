# NP Notes: безопасная синхронизация через приватный GitHub

**Статус: экспериментальная ветка / PR #86. НЕ включено в установленную версию.**
Тесты используют только синтетические папки. Рабочий `Launcher/Data` не читался.

## Модель

- Каждая заметка (по UUID) шифруется отдельно: AES-256-GCM с ключом из scrypt
  и репозиторно-зависимой солью. При каждом обновлении новый случайный nonce.
- GitHub хранит `notes/<UUID>.npn`: зашифрованный ZIP с `note.json`
  и обычными вложениями. GitHub видит UUID, размер и частоту изменений, но не текст.
- Не передаются `password_manager`, `password_manager_visible`, кэши,
  резервные JSON, локальные настройки Choice, DPAPI-черновики, журнал ошибок,
  секреты и данные других приложений.
- Вложения включены; текущий лимит сжатого снимка одной заметки — 20 МиБ.
  При превышении лимита синхронизация этой заметки останавливается с ошибкой,
  **оригинал не изменяется**. Git LFS пока не поддерживается.
- Перед любой сетевой передачей GitHub API проверяет, что репозиторий
  **private**. Публичный репозиторий и отсутствие прав блокируют обмен.
- При сетевой ошибке обычное локальное сохранение продолжается. Фоновая
  проверка каждые 5 минут повторяет попытку; нет блокировки GUI.
- Полученные файлы сначала сохраняются **зашифрованными** в
  `Data/NoteSync/inbox`. На GUI-потоке проверяются пароль, UUID,
  пути вложений и локальная контрольная сумма. Активная заметка не заменяется.
- Если два устройства изменили одну заметку, удалённая версия сохраняется
  в `Data/NoteSync/conflicts` как шифрованная копия, локальная остаётся.
  Никакого автоматического удаления заметок и вложений.
- Токен GitHub и пароль шифрования хранятся в
  `Data/NoteSync/credentials.dpapi`, защищённом для текущего Windows-профиля.
  При переносе на другой компьютер необходимо заново ввести *тот же* пароль
  шифрования. Не включать этот файл в синхронизацию или общий репозиторий.

## Установка/подключение после прохождения проверок и отдельного разрешения

1. Создать **пустой приватный** репозиторий, например `NP-Notes-Sync`.
   Не использовать репозиторий `CODE`.
2. Выдать отдельный fine-grained token с доступом только к этому
   репозиторию и разрешением `Contents: Read and write`; не публиковать
   его в чате, скриншотах, CI, журнале и конфигурации Choice.
3. После установки поддерживаемого пакета `cryptography` на каждом ПК
   выполнить под Windows консольным Python:
   
   ```powershell
   python tools/configure_np_notes_sync.py --launcher-root 'C:\WORK\NP\Launcher' --repository 'OWNER/NP-Notes-Sync' --apply
   ```

   Утилита запросит токен и дважды пароль без отображения ввода,
   убедится, что репозиторий закрытый, сохранит DPAPI-секреты и включит
   интервал 5 минут. Без `--apply` действует режим проверки.
4. Закрыть и повторно открыть NP Notes. Следующий запуск синхронизации —
   примерно через 12 секунд после запуска, затем каждые 5 минут.
5. Для второго компьютера повторить локальное подключение с тем же
   паролем шифрования. Токен может быть другой.

**Не запускать эти шаги на реальных заметках, пока PR находится в черновике.**
Пароль шифрования необходимо хранить вне GitHub: при потере пароля
существующие удалённые заметки расшифровать нельзя.

## Ограничения и обязательные проверки перед релизом

- Протестировать настоящую приватную тестовую репозиторию и отдельные
  синтетические Notes на Windows 11, включая вход через Choice Runtime.
- Проверить поддержку cryptography в переносимом Runtime и выпуск
  обновления без удаления `Data`.
- Добавить интерфейс отображения очереди, конфликтов, ошибок синхронизации
  и безопасное ручное разрешение конфликтов.
- Проверить импорт вложений после переименования заметки, обработку больших
  вложений, многократный одновременный запуск и отключение питания на записи.
- Проверить восстановление выбранной заметки с учётом локального формата
  папок, истории и ремайндеров. До этого не включать функцию в main.
- Сделать резервную копию данных на независимый носитель перед первым
  подключением реального пользователя.

## Критерии безопасности

- Без файла `Data/NoteSync/config.json` модуль не начинает сетевой обмен.
- Без корректного DPAPI-файла/переменных окружения нет незашифрованного fallback.
- Сбой GitHub или отсутствующий интернет не блокирует локальные заметки.
- Гонка двух изменений и SHA-конфликт GitHub не перезаписывает чужие файлы.
- На удалённую сторону никогда не отправляются открытые текстовые данные,
  даже в диагностических сообщениях.
